## 字体下拉"全是空白"的修复（用户截图反馈：选择字体怎么都看不见）

### 根因：字段名再次没对齐调用方

`app.js` 的 `loadEditor()` 是按 `f.name` 渲染 `<option>` 的，而本地 API 返回的是
**字符串数组**（`families: ['Microsoft YaHei', ...]`）—— `f.name` 恒为 undefined，
`esc(undefined)` 得到空串，于是 232 个选项的标签**全部空白**，下拉一打开是一片
巨大的空白面板，且**不报任何错**。

Python 版 `/api/fonts` 的真实契约是：
```
families: [{ name, bold, user, files }]     # 不是字符串数组
user_count / user_dir
```
本地实现已按此对齐（`FontRegistry.listForUi()` 返回同形对象，排序语义也沿用原版：
导入在前 → 中文 → 其他 → 通用族收尾）。

> 这是同类错误的**第三次**：`user_count`/`families`（第一次）、`family` vs `name`（这一次）。
> 教训固化：**跨端实现同一个接口时，字段名对着调用方核，别对着自己的实现核。**
> 这类错误不抛异常，只表现为"空列表/空标签"，极难从日志发现。

### 顺带把选择体验做扎实

- 加了**字体搜索框**（`#fontFilter`）：两三百个字体靠原生 select 找字太难
- 下拉改成 **`size=8` 的内嵌列表**（不再用原生弹出层 —— 几百项会铺满整屏，
  用户截图里那个"一屏空白"就是这个）
- 按来源**分组**：★ 已导入 / 中文字体 / 其他字体 / 通用
- 选中项不在当前过滤结果里时，补一个「当前选择」分组，避免静默跳回"自动匹配"
- **联动**：手动选字体 = 自动关掉「自动匹配」；重新勾上自动匹配 = 清掉手动指定
  （否则勾选框状态与实际渲染用的字体对不上）
- `?v=` 脚本版本号推进到 3.3

### 两个排查教训

1. **探针判据别死盯某个字面**。我为"初始化完成"写的判据是状态栏出现「服务就绪」，
   但复用了浏览器 profile 时页面会**自动恢复上次编辑**，状态栏变成
   「已恢复上次的编辑」→ 探针误报失败。正确判据是"**没有报错**"
   （排除 无法连接/失败/超时/准备中）。
2. **无头浏览器不能用来判断"用户浏览器支不支持某个 API"**。`window.queryLocalFonts`
   在无头下受页面可见性影响，且 `navigator` 上根本没有（挂在 `window` 上）。
   判断可用性要用真实环境，或至少区分"无头限制"与"不支持"。

## 长时间生成超时：改成流式心跳（用户第二次报「生成超时」）

### 关键认知：边缘的超时是「空闲」超时，不是「总时长」上限

一直以为 Cloudflare 边缘约 100s 是单请求总时长上限，所以只能把 `MAX_UPSTREAM_TIMEOUT`
压在 90s。**这是错的**。

实验：临时加一个 `/api/cf/streamtest?seconds=150&step=10`，每 10 秒吐一行心跳，
持续 150 秒。结果 —— **HTTP 200、151 秒完整送达、最后一帧也收到了**。
结论：那条 100s 是"**没有数据流动**"的判据。只要持续有字节在流，就能一直跑。

> 这个"先做一次最小实验验证平台边界假设"的动作值得固化：
> 一条 20 行的临时路由，换来一个决定性结论，比读十篇文档都快。

### 落地方案：NDJSON 流式 + 心跳保活

- **协议**（`routes/image.js`）：`start` → 每 5 秒一行 `tick` → `done` / `error`
- **两个上限分开**：`MAX_UPSTREAM_TIMEOUT=90`（一次性，受 100s 空闲约束）、
  `MAX_STREAM_TIMEOUT=300`（流式，靠心跳保活）。
  前端默认走流式并传 `stream=1`。
- **错误也走流内**（`{"type":"error"}`），HTTP 状态始终 200 ——
  响应头在建流时就发出去了，客户端必须读流才知道成败，**不能只看 `response.ok`**。
- **客户端断开能止损**：`ReadableStream.cancel()` 停心跳，
  并通过 `AbortSignal` 把上游请求一起 abort（`gen.js` 新增 `opt.signal`），
  免得任务跑完却没人接收、白耗中转站额度。
- **界面实时报进度**：`loadingSub` 显示「已等待 Ns」，超过 60 秒追加提示。
  慢的时候用户至少知道还活着。
- 心跳间隔可用 `STREAM_HEARTBEAT_MS` 配置（测试里设 100ms，不必真等）。

| 项 | 结果 |
|---|---|
| 实验：150s 流式响应 | ✅ 完整送达（首字节 1.06s，总 151s） |
| 真实上游流式出图 | ✅ 1.7s 首字节 → 15 行心跳 → 75.8s 出图（总 82.9s），2.27MB |
| 前端解析（页面内伪造流） | ✅ 7/7：心跳递增 2s→6s、跨 chunk NDJSON 正确、结果图渲染 |
| e2e | 66/66（新增 8 条流式用例：心跳、超时收口、done/error 收尾、非流式兼容） |

### 第三个"看着没反应、其实全错"的坑（这次是测试工具）

写前端流式验证时连踩三条弯路，都表现为"点了生成、界面没反应"：

1. **CDP 的 `Fetch` 域拦截**：请求被 pause 住，但 `Fetch.requestPaused` 事件收不到，
   页面一直转圈 → 换成注入脚本改写 `fetch`。
2. **本地 http 假上游**：https 页面发 http 请求属**混合内容**，被浏览器直接拦掉
   （`net::ERR_FAILED`，且服务端根本没收到请求）→ 最终改为
   **在页面内构造 `ReadableStream` 伪造响应**：不走网络，但起止时序、分块节奏、
   NDJSON 协议与真实服务端一致，零成本无跨域问题。
3. **页面草稿水合**：生成页加载后有异步的"恢复上次草稿"，会把输入框重写。
   设完值立刻点生成，可能刚好被它覆盖 → `generate()` 前置校验直接 return，
   表现成"点了没反应"。改成"填值 → 校验 → 点击 → 确认真的进入生成流程"的重试环。

**教训**：这类"点了没反应"要先回答三个问题 —— 请求发出去了吗？被谁拦了？
页面走到哪一步了？诊断脚本要把"改写标记 + 输入框实值 + 状态元素可见性 +
网络失败原因（`Network.loadingFailed`）"一次性打出来。

## 合并为单页双视图（用户反馈：切来切去等得久）

### 先量化，再动手

写了 `tools/probe_nav.mjs` 测各次跳转，结论很清楚 —— 问题不在"加载慢"，
而在**切回无痕改字要 5.77s**：

| 动作 | 耗时 | 原因 |
|---|---|---|
| 首次进改字页 | 10.69s | 含 39MB 模型下载 |
| → 生成页 | **0.28s** | 轻量，只拉一个接口 |
| → 切回改字页 | **5.77s** | 重新执行 `engine/boot.js`，WASM + OCR 模型重新装配 |

### 做法：`/` 单页装两个视图

`index.html` 现在的结构：

```
<main>
  <div class="view-embed on" id="viewEdit">   ← 改字（原 index.html 主体）
  <div class="view-embed" id="viewImages" hidden>  ← 生成（原 image.html 主体）
</main>
```

- `app.js` 加**视图路由**：`#edit` → 改字；`#create/#combine/#projects…` → 生成
- `image.js` 加**嵌入模式**：`EMBEDDED()` 为真时不再自己改 hash，
  而是调 `window.WBShowImages(key)` 让外层切视图
- 侧边栏链接统一改成 `/#xxx`，`shell.js` 的 `currentKey()` 同时认 `/` 与 `/image`
- **删掉 `web/image.html`**（内容已并入）

### 效果（线上实测）

| 指标 | 改造前 | 改造后 |
|---|---|---|
| 改字 → 生成 | 0.28s | **15ms** |
| 生成 → 改字 | **5.77s** | **15ms** |
| 是否重新加载页面 | 是（每次跳转） | 否（文档加载次数恒为 1） |

`probe_views.mjs` **13/13**、e2e **67/67**、compat **14/14**。

### 这一轮踩的四个坑（全是"看着对、其实错"）

1. **提取主区时漏了 `</main>` 之后的内容** —— 灯箱、弹层、toast 容器都在那儿，
   少了它们 `image.js` 初始化直接抛错。教训：**搬 DOM 要搬"页面的全部"，不是"看着像主体的部分"**。
   搬完用脚本核对 `js 里 \$('x') 用到的 id` vs `html 里实际有的 id`。
2. **`const` 暂时性死区**：`EMBEDDED` 定义在 539 行，而 `init()` 在 443 行就执行 →
   `Cannot access 'EMBEDDED' before initialization`。**立即执行的 IIFE 用到的常量必须定义在它之前**。
3. **`hash` 为空时点击导航不生效**：外层只监听 `hashchange`，而 `/` → `/#create`
   这一步的事件在某些时序下收不到。改成"内层主动喊外层"（`WBShowImages`），不依赖事件。
4. **探针自己的错**：
   - `cdp.evaluate(expr, false)` 不取返回值，`ok` 恒为 `undefined` → 误报"点击失败"
   - 侧边栏是 `shell.js` 异步渲染的，点击前没等它出现 → 元素拿不到、点击静默失败
   - 探针要**兼容多种起始状态**（全新会话 / 已恢复会话 / hash 空或非空）

### 附：新增 `sync-assets-safe.mjs`

原来的 `sync-assets.mjs` 用 `rm -rf public` 重建，沙箱里会被安全删除机制拦下
（"Some operations were aborted"），且失败后 deploy 照跑 → 线上留旧文件。
新脚本**只覆盖不删除**，并加了两道自检：
① 关键文件必须存在 ② `index.html` 必须含两个视图容器。
另外补了 `pruneOrphans()`：源端删掉的文件会在目标端一并清理
（这次就靠它发现 `public/static/image.html` 残留 —— 只覆盖不删除的副作用）。

线上版本 `614ae357`；`/image` 保留为兼容入口（浏览器端跳转，能保住 fragment 锚点）。

## 合并后的三个问题（用户截图反馈）

### 1. 除改字页外其他视图全空白 —— **DOM 嵌套错了**

上一轮合并时，`#viewEdit` 的闭合 `</div>` 漏了，导致 `#viewImages` 被**嵌进 `#viewEdit` 里面**。
于是切到生成视图时：外层把 `viewEdit` 设为 `hidden` → 里面的 `viewImages` 跟着被隐藏 → 一片空白。

**排查手法值得记**：写个脚本爬祖先链和兄弟节点，一眼看穿嵌套：

```
#viewImages 的祖先链：
  div#viewImages.view-embed  [0x0]
    ← div#viewEdit.view-embed.on  [692x487]   ← 本该是兄弟，结果成了父子
      ← main.main
它的兄弟节点：header | div | footer | viewImages
```

**教训**：手工拼大的 DOM 块之后，**必须验证嵌套关系**，不能只看"元素存在"。
`grep id="xxx"` 只证明它在文件里，不证明它在正确的层级。

### 2. 提示词清空（新功能）

- `#btnClearPrompt`：有内容才显示，清空后自动收起（空框旁边挂个没用的按钮很难看）
- 顺手加了**字数显示**（原来只有"可选"两个字）
- 支持 **Esc 清空**，但只在**有内容时拦截** —— 没内容就让事件冒泡（那个 Esc 是关灯箱/弹层的）
- 刷新时机要全：`input` / 切工具（`applyDraft`）/ 点 chip / 清空本身，四处都要调 `updatePromptMeta()`

> 踩了一下：`touch()` 只负责存草稿、**不管界面**，清空后我漏了刷新 → 字数不归零、按钮不隐藏。
> 分离"数据落盘"和"界面刷新"两个职责时要留意，别指望一个函数干两件事。

### 3. 「自由生成」开启参考图（用户明确要求）

原来是 `refs: { min: 0, max: 0 }`（纯文生图），现改为 `{ min: 0, max: 4 }`：

- 选传：不传=纯文生图，传了=带参考
- `wrap(p, hasRefs)` 新增第二个参数 —— 有参考图时才加一句"参考所给图片的风格/构图/主体"，
  **不写"必须保持主体一致"那种强约束**（那是「图像融合」的职责）
- 上传框提示按 `min` 区分：`min=0` 说"**选填，最多 N 张**"，别写"需要 0~4 张"（读起来很怪）
- `renderRefZone()` 的 `noRef` 判定本来就是 `max === 0`，改配置就自动生效
