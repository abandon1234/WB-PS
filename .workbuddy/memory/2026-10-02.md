## 编辑文字面板：新增「笔画粗细」粗细微调

需求：样式区原来只有「加粗 / 斜体」两个 0/1 开关，加粗只是切字体 Bold 变体，
遇到"就差一点点"的场合没法微调。新增一条滑块（-20 ~ +20 档，0 = 自动）。

**数据流**：UI 存 `edit.weight_bias`（整数档位）→ 引擎换算成相对字号的描边偏移
`stroke_bias = weight_bias * WEIGHT_STEP`（WEIGHT_STEP = 0.0025，即 1 档 = 字号 0.25%
≈ 自动校准自身 0.45px 容差，故 1 档就是最小有意义步长）→ `render(stroke_bias=...)`。

改动文件（**两条引擎路径必须同步改**）：
- `web/index.html` / `web/style.css`：`.subfield` 滑块 + 读数 + 归位按钮
- `web/app.js`：`loadEditor` 回填、滑块/归位事件、`isChanged` 加 `weight_bias`、`weightLabel()`
- `web/engine/index.js`：`WEIGHT_STEP`、`editParams` 翻译、`isDirty` 判断
- `web/engine/render.js`：`stroke_bias` 参数与叠加逻辑、`refreshStrokeInfo()`
- `app/pipeline.py`：`WEIGHT_STEP`、`_edit_params` 翻译、`_dirty` 判断
- `app/text_renderer.py`：`stroke_bias` 参数与叠加逻辑、`refresh_stroke_info()`

### 关键结论（踩坑，下次直接照做）

1. **人工微调绝不能进 `build()`**。第一版把 `bias` 塞进 `build()`，自动笔画校准闭环
   测到的笔画里就含了人工偏移 → 闭环把它当"误差"反向补偿掉（微调白做），
   还会吐出「已校准：原图 9.0px → 渲染 13.7px」这种错读数。
   正确做法：**闭环跑完后再 `stroke_rel += bias`**，之后任何重建（含过宽缩字号）
   自动带上且只叠一次，不需要额外的 baked 标志位。
   验证：目标笔画 14px 时，bias=0 得 13.73px / 补描边 2.99px；bias=+10 档得 18.99px /
   补描边 5.97px（2.99 + 0.025×119）—— 纯净叠加。
2. **负向受限**：PIL/canvas 的描边只能向外扩，没法腐蚀笔画。"更细"只能靠
   `thinnerVariant` 换字重变体，换不成时给明确警告（不是静默无效）。
   实测 Microsoft YaHei 无 Light 变体时负向微调无效，属预期。
3. **描边像素 ≈ 2× 视觉增量**：`stroke_width` 是向外扩 N px（PIL 语义），
   所以笔画宽度实测变化约等于 `stroke_added` 的 2 倍，与既有自动校准口径一致。
4. **顺手修的老问题**：`stroke_info` 原来在「过宽缩字号」之前算，字号缩小后读数
   是错的（界面拿它显示"笔画 X→Ypx"）。加了 `refreshStrokeInfo()` 在重建后重测。

### 顺手修掉的部署配置 bug：`routes` 从未生效

部署时 wrangler 报 `Unexpected fields found in assets field: "routes"`。

**根因**：TOML 里一张表会一直延伸到下一个表头。`wrangler.toml` 把 `routes = [...]`
写在了 `[assets]` 之后，于是被解析成 `assets.routes`，**顶层没有 routes**，
wrangler 直接忽略 —— 配置里那段"写进配置是为了防止 deploy 覆盖域名绑定"的注释
实际从未生效。线上能访问只是因为绑定还留在 Cloudflare 侧没被摘掉。

**修法**：把 `routes` 移到 `name` / `main` / `compatibility_*` 之后、第一个 `[table]` 之前。
**判断是否生效**：看 deploy 输出的 triggers 里有没有 `ps.ysw69.dpdns.org (custom domain)`。
修复后该行出现，warning 消失。

**连带副作用**：`routes` 真生效后 wrangler 默认禁用 `workers_dev` 与 Preview URL
（部署日志会多两条 warning）。已显式写 `workers_dev = false` / `preview_urls = false`
并注明缘由；要海外/VPN 备用入口就改回 true。实测 workers.dev 地址已不可达（符合预期）。

### 教训

`wrangler.toml` 改完不要只看 "Deployed" 就当成功 —— **必须核对 triggers 里的域名行**，
并且部署日志里的 WARNING 要逐条读。这次若没读那条 warning，域名绑定会一直是"假生效"。
