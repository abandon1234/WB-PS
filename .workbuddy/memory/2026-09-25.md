## 新增：图像工坊模块（中转站 gpt-image-2 生图）

用户要求新增**独立**的图片生成模块，与文字处理模块区分开、独立页面路由、
优化 UI，并提供中转站配置的后台管理。给了测试参数（`code.linlong520.com`
+ 一把 sk- key）和提示词"生成一个小狗"。

### 中转站协议探测（关键，全靠实测得出）

拿到需求时先探测协议而不是照 OpenAI 文档写，结果三条都出乎意料：

1. **参照图不能用标准的 `/v1/images/edits`** —— 该接口返回 **HTTP 200 但
   `data: []`**（空数组），试过 `image` / `image[]` / 加 `response_format`
   都一样。
   **正确姿势**：走 `/v1/images/generations`，加一个 `image` 字段
   （`data:image/png;base64,...` 字符串）。
   用"洋红底 + 中央白方块"的强特征参照图验证过：生成结果洋红占比 **85.8%**、
   白色 14.1%，证明确实作为条件输入生效（不是被忽略）。

2. **`b64_json` 返回的是 data URL**，带 `data:image/png;base64,` 前缀，
   不是纯 base64。直接 `b64decode` 会报
   `number of data characters (...) cannot be 1 more than a multiple of 4`。
   需要先剥前缀、再补 padding。

3. 内容被拦截时可能返回 **HTTP 200 + 空 data**，必须在客户端显式识别并提示，
   否则前端会拿到空数组干瞪眼。

响应里还附带 `image` / `image_url` / `url`（`http://69.33.x.x:4141/media/*.png`）
字段，`b64_json` 优先用。

### 实现要点

- `app/image_gen/` 独立包：`config.py`（配置存储）/ `client.py`（API 客户端）
  / `routes.py`（页面与接口）
- 配置存 `data/image_providers.json`，`.gitignore` 排除（含 API key）
- 编辑配置时 **`api_key` 传空字符串 = 不修改**，避免前端拿到打码值后覆盖真实 key
- 禁用当前配置时自动切到下一个可用配置
- 生成走 `run_in_threadpool`，不阻塞事件循环
- `client._opener()` **显式清空代理**：本机常驻代理环境变量会干扰对外请求
- 页面 `/image`、`/static/image.{css,js}`，与文字处理模块完全解耦

### 踩的两个坑

**坑 1：FastAPI 把 multipart 里的空字符串当成"字段缺失"**

`prompt: str = Form(...)` 收到空字符串时返回 **422 Field required**
（`type: missing`），而不是进入业务校验。用户看到的是技术性的英文错误。
改为 `Form(default="")` + 业务层校验，才能给出"提示词不能为空"这种可读提示。

**坑 2：`git add -A` 把快照 zip 一起提交了**

`tools/snapshot.py` 默认输出到项目上一级（`D:\MyCode\`），但某次实际落在了
项目根，于是被 `git add -A` 收进仓库。已 `git rm --cached` 移出 + 实体移到上级
+ `.gitignore` 加 `*.zip` 兜底。**教训：任何二进制产物类文件都应先进 gitignore。**
