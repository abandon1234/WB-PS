## 新增：图像工坊模块（中转站 gpt-image-2 生图）

用户要求新增**独立**的图片生成模块，与文字处理模块区分开、独立页面路由、
优化 UI，并提供中转站配置的后台管理。给了测试参数（`code.linlong520.com`
+ 一把 sk- key）和提示词"生成一个小狗"。

### 中转站协议探测（关键，全靠实测得出）

拿到需求时先探测协议而不是照 OpenAI 文档写，结果三条都出乎意料：

1. **参照图不能用标准的 `/v1/images/edits`** —— 该接口返回 **HTTP 200 但
   `data: []`**（空数组），试过 `image` / `image[]` / 加 `response_format`
   都一样。
   **正确姿势**：走 `/v1/images/generations`，加一个 `image` 字段
   （`data:image/png;base64,...` 字符串）。
   用"洋红底 + 中央白方块"的强特征参照图验证过：生成结果洋红占比 **85.8%**、
   白色 14.1%，证明确实作为条件输入生效（不是被忽略）。

2. **`b64_json` 返回的是 data URL**，带 `data:image/png;base64,` 前缀，
   不是纯 base64。直接 `b64decode` 会报
   `number of data characters (...) cannot be 1 more than a multiple of 4`。
   需要先剥前缀、再补 padding。

3. 内容被拦截时可能返回 **HTTP 200 + 空 data**，必须在客户端显式识别并提示，
   否则前端会拿到空数组干瞪眼。

响应里还附带 `image` / `image_url` / `url`（`http://69.33.x.x:4141/media/*.png`）
字段，`b64_json` 优先用。

### 实现要点

- `app/image_gen/` 独立包：`config.py`（配置存储）/ `client.py`（API 客户端）
  / `routes.py`（页面与接口）
- 配置存 `data/image_providers.json`，`.gitignore` 排除（含 API key）
- 编辑配置时 **`api_key` 传空字符串 = 不修改**，避免前端拿到打码值后覆盖真实 key
- 禁用当前配置时自动切到下一个可用配置
- 生成走 `run_in_threadpool`，不阻塞事件循环
- `client._opener()` **显式清空代理**：本机常驻代理环境变量会干扰对外请求
- 页面 `/image`、`/static/image.{css,js}`，与文字处理模块完全解耦

### 踩的两个坑

**坑 1：FastAPI 把 multipart 里的空字符串当成"字段缺失"**

`prompt: str = Form(...)` 收到空字符串时返回 **422 Field required**
（`type: missing`），而不是进入业务校验。用户看到的是技术性的英文错误。
改为 `Form(default="")` + 业务层校验，才能给出"提示词不能为空"这种可读提示。

**坑 2：`git add -A` 把快照 zip 一起提交了**

`tools/snapshot.py` 默认输出到项目上一级（`D:\MyCode\`），但某次实际落在了
项目根，于是被 `git add -A` 收进仓库。已 `git rm --cached` 移出 + 实体移到上级
+ `.gitignore` 加 `*.zip` 兜底。**教训：任何二进制产物类文件都应先进 gitignore。**

## 重构：TanStack 风格界面 + 后台隔离 + 浏览器端作品库

用户给了 TanStack AI 的界面截图，要求：把界面改成类似风格、Projects 界面显示
已保存/生成的图片、图片缓存到用户浏览器（程序不保存任何东西）、
搞独立的后台管理界面、**不要在前端暴露 API Key**。

### 密钥隔离（本次最核心）

**先摸清原来的泄露面**：`/api/image/overview` 与 `/api/image/providers` 直接把
明文 key 下发给浏览器（`config.public_view()` 的 `reveal` 默认是 `True`），
前端抽屉里能直接看到 `sk-...` 全串。这等于把密钥公开给任何能打开页面的人。

改法（六层）：

1. 配置类接口全部搬到 `/api/admin/*`，两个旧接口**直接删除**（返回 404）
2. `public_view(reveal=False)` 改为默认打码；生成页只保留
   `/api/image/status`（只回 `ready/model/sizes/message`）与 `/api/image/generate`
3. 新增 `app/image_gen/admin_auth.py`：PBKDF2-HMAC-SHA256（12 万次迭代 + 16 字节
   随机盐）存哈希；**不预置任何默认口令**，首次访问走 `/api/admin/setup` 自行设定
4. 会话令牌 = `HMAC-SHA256(secret, exp)`，放 `HttpOnly; SameSite=Lax` Cookie；
   同时兼容 `X-Admin-Token` 头给脚本用。改密码时轮换 `secret`，旧令牌全失效
5. 同 IP 连续 6 次失败锁定 5 分钟（内存计数，带窗口滑动与容量上限）
6. **测试里加了专门的泄露断言**：拿真实 key 字符串去全量扫描状态接口和所有
   后台响应的 JSON，出现即失败

### 前端作品库（拆表是关键）

图片存浏览器 IndexedDB。第一版把「元数据 + 原图字节」放同一张表，
**画廊 `list()` 走游标时会把每张 2MB 原图都读进内存**——50 张就是 100MB 的 I/O。
改为拆两张表：`meta`（元数据 + 360px 缩略图）、`blobs`（原图字节）。
画廊只读缩略图，点开灯箱才按 id 取原图。DB_VER 1→2 升级时直接丢弃旧表
（本地缓存，无迁移价值）。

存 `ArrayBuffer` 而非 Blob/DataURL：DataURL 体积膨胀 33%，
Blob 在老 Safari 的 IDB 里有兼容问题。

### 多参照图（推翻了上一轮的结论）

上一轮记录「只稳定支持单张」。这轮专门写了 `tools/probe_multiref.py` 去验证：
**`image` 传数组完全可行**——洋红底白方块 + 青底黑三角两张强特征图，
结果图洋红 75.3% + 青 19.3%，两张都被采纳。`images` 传数组也可以（但慢一倍）。
所以前端不必强制拼图，只在被内容审核拦下时才降级拼图重试。

### 踩的坑

**坑 1：从作品库点不回去生成页。**
`selectTool()` 里 `if (t.id === S.tool.id) return;` 提前返回——
在作品库视图下，工具项虽然不高亮但 `S.tool` 没变，
所以点击当前工具完全无反应。修法是先 `switchView('generate')` 再判同不同。

**坑 2：`tools/image_api_test.py` 的 `Client.get()` 没带鉴权头。**
`_headers()` 只在 `send()` 里用了，`get()` 直接 `op.open(url)`，
于是后台列表请求拿到 401，测试报"0 条配置"。断言本身是对的，是工具写歪了。

**坑 3：`--headless --screenshot` 截不到需要交互/数据的界面。**
Edge 的 CLI 截图没法注入 IndexedDB、也没法登录，还会丢 URL 里的 `#fragment`。
改用 **Node 22 内置 WebSocket 直连 CDP**（`tools/ui_shot.js`）：
先 `Runtime.evaluate` 播种数据/登录，再 `Page.captureScreenshot`。
不用装 Playwright 的 500MB Chromium，直接复用系统 Edge。

## 统一外壳：把 `/` 也纳入同一套界面 + 修两个交互 bug

用户给了两张标注截图：一是把文字处理页"搞进里面去"，二是标红的两个地方有 bug。

### 抽出共享外壳

`web/shell.css` + `web/shell.js`，`/` 与 `/image` 共用：

- 侧栏导航改为普通 `<a href>`：`/`、`/image#create|combine|portrait|product`、
  `/image#projects`。跨页跳转与浏览器前进后退天然可用
- 图标雪碧图搬到 shell.js 统一注入，各页 HTML 不再各抄一份
- 侧栏作品数徽标与容量条由 shell 统一渲染，页面侧只调 `WBShell.refresh()`
- 文字页原来的右侧栏改名 `.inspector`（避开外壳的 `.sidebar`），
  其 321 行 CSS 只换 `:root` 令牌 + 几处硬编码蓝色就完成了换肤

**深链的关键坑**：`history.replaceState` **不触发 `hashchange`**。
页内切工具时要额外调 `WBShell.syncActive()` 手动重画侧栏高亮。
另外 CDP 的 `Page.navigate` 对「只有 fragment 变化」的同文档跳转不可靠，
测试里改用 `location.hash = '...'` 赋值。

### Bug ①：侧栏折叠后展不开（会把自己锁死）

折叠态品牌行仍横排（logo 27px + gap 9 + 按钮 26px），而侧栏只有 62px，
折叠按钮被压成 **0 宽**并被 `.sb-brand` 盖住——`elementFromPoint` 命中不到。
用户点一次就再也收不回来。窄屏媒体查询还**无条件**把侧栏压成 62px，
连 `.collapsed` 类都不看，让问题更隐蔽。

修法：折叠态品牌行改竖排（logo 上、按钮下，28×28 保证命中面积）；
把「强制折叠」从媒体查询移进 JS（无用户偏好且窗口 < 1100px 才自动折叠一次）；
`title`/`aria-label` 随状态切换。

### Bug ②：尺寸/数量菜单关不掉，一直浮在界面上

`closePop()` 只把遮罩 `#popWrap` 设成 `hidden`，而 `.pop` 面板是
**`document.body` 的子节点**（不在遮罩里），`position: fixed` 又不受
`body{overflow:hidden}` 影响——遮罩没了，面板还留在屏幕上；
只有下次打开别的菜单才会被 `openPop` 里的 `old.remove()` 顺手清掉。

修法：面板挂进遮罩内部，隐藏遮罩即隐藏菜单；定位改成先量尺寸再摆位，
上方放不下翻下方，都不行再夹进视口。

### 环境坑：沙箱的 safe-delete 会拦 Python 的 os.remove

`app/fonts.py` 的 `remove_user_font` 调 `os.remove`，
被 `sitecustomize.py` 的 bulk-delete guard 拦下并 `raise SystemExit(1)`
（`scope: turn`，本轮累计删除超阈值就触发）。
**`SystemExit` 继承自 `BaseException`，`except OSError` 捕不到**，
于是接口直接 500 裸奔。已在 `main.py` 里 `except (OSError, SystemExit)`
兜住并回可读中文提示；`api_test.py` 增加 SKIP 概念，
把这类环境限制与真实失败分开统计。
