## 生成工具四合一（commit 26ef277）

用户要求：把侧栏的四个生成工具（自由生成 / 图像融合 / 人物写真 / 商品图生成）

做法：合并为单一工具 `generate`（名称「AI 生成」），语义由「有没有传参考图」决定 ——
不传 = 纯文生图（提示词原样发送），传 1~4 张 = 以参照图主体为准生成。
原来四种玩法的差异改由提示词表达，chips 里给了对应例子。

改动点（也是下次改这块的入口清单）：

- `web/shell.js`：NAV 收敛为 无痕改字 / AI 生成 / 作品库；`LEGACY` 表把老 hash
  （create/combine/portrait/product）映射到 generate，侧栏高亮不丢。
- `web/image.js`：`TOOLS` = `[TOOL]`（保留数组形状，遍历逻辑不用改）；
  `normToolId()` 归一老 id；`preloadDrafts` 合并前的老草稿按 `savedAt` 取最新一条接手，
  参照图用 `legacyRefsKey` 按老键读一次（`hydrateDraft` 里）。
- `web/app.js`：`IMAGE_KEYS` 加 `generate` 且保留老 key；默认 key 改 generate。
- `cloudflare/src/index.js`：`LEGACY_PAGE["/image"]` → `#generate`。
- `cloudflare/src/routes/image.js`、`app/image_gen/routes.py`：TOOL_NAMES 加
  `generate: "AI 生成"`，老 key 保留（作品库旧记录回显用）。
- `web/image.css`：`.chip` 加 `flex: 0 0 auto; white-space: nowrap;` ——
  中文短语可断行，窄栏里会被 flex 压成「一个字一行」的小方块（原来就这样）。
- `tools/probe_views.mjs`：断言跟上新结构，新增侧栏三项 / 标题 / 上传区文案 /
  空态提示 / 老 hash 归一 等检查。`tools/serve_dev.mjs` 补 `/image` 兼容入口，
  否则本地自检看不到老链接行为。

验证：`node tools/probe_views.mjs --base http://127.0.0.1:8790` **19 条全过**，
无页面 JS 异常。

## 新功能方向分析（未定案，待用户选）

用户问：除生图外，还能做哪些日常/工作场景的功能。已联网核过需求，结论与候选池如下。

**战略判断**：核心资产不是生图，而是「搜索-检测 → 识别 → 风格分析 → 原位擦除 → 原样式重绘」
这条**图片文字逆向工程**管线（`web/engine/{ocr,style,erase,render,fonts}.js`，全在本机 ONNX）。
新功能应沿这条管线外扩，不要新开品类。

**联网核到的市场信号**：

- 图片翻译（保留排版）已是付费品类（TranslateImage / Transpic / AI Image Translator，
  约 $9.9/月），其官方卖点写的「文字移除要完美保留背景」「保留字体与排版」
  = 本项目的 erase + style + render。
- 分享前打码：DAMA / 打码隐格等三款产品，卖点清一色「设备端识别、不上传、离线、抹 EXIF」，
  但**只有手机 App，Web 端是空位**。
- 图片转 Excel：市场大（Lido 9.4/10，企业版 $499/mo），免费工具通病 = 要上传 + 带水印 + 复杂表格失真。
- 趋势：2026 浏览器本地 AI 已成品类，业内点名「混合管线：轻任务本地跑、重任务走云端」= 本项目现有架构。

**候选池（按复用度分层）**

- T0 复用现有管线：图片翻译·原位换字 / 批量改字 / 本机打码脱敏 / 截图取文字
- T1 加轻模型或纯算法：截图转表格 xlsx、证件照制作、去背景抠图、图片批处理、二维码条码、批量水印
- T2 需新模型或云端：老照片修复超分、文档转 Markdown、手写体识别、云端团队素材库、短链分享

**已向用户标注的坑（做的时候别忘了）**

1. 现装的是 `ch_PP-OCRv3`（中英），图片翻译需换多语言识别模型，这步不是零成本。
2. 打码不要宣称「无法还原」；敏感信息默认走色块或已有的「抹字」（竞品只能模糊，这是优势）。
3. 翻译文本必须出境，UI 要明说（沿用现在「亮出实际发送内容」的做法）。
4. 截图转表格赢在准确率（合并单元格 / 复杂表头），别急着铺功能。
5. 证件照只做换底与规格排版，不碰换脸 / 身份证。

**建议顺序**：截图取文字 + 本机打码（共用检测结果，一起做）→ 图片翻译 → 截图转表格。
待用户确认「给谁用」后再出实施方案。

## 定案与实施方案（docs/plan-text-workshop.md）

用户定调：**不是对外产品，但保留这个方向；先自己用顺手，按上面的顺序推。**

已产出第一版实施方案 `docs/plan-text-workshop.md`，关键结论：

- **一个前半段、三种输出**：三个新功能共用 `engine/index.js` 的 `detect()`/`analyze()`，
  差别只在后半段。取文字/打码只需 `detect()`（较快），翻译要 `analyze()`（要样式）。
- 翻译的重绘**直接复用现有 `applyEdits()`**，溢出靠 `editParams()` 已有的
  `auto_fit` / `font_scale`，不新写排版逻辑 → 渲染语义零改动，
  因此**不需要按"两条等价路径"约定做双端同步**，Python 侧只补 translate 代理。
- **新建视图 `#text`「文字工坊」**（NAV 一项 + 三模式：取文字/打码/翻译），
  不塞进「无痕改字」视图（理由已写进方案第 2 节与 MEMORY.md）。
- 打码导出走 `canvas.toBlob()` 重编码 → **天然不带 EXIF**，不需手写元数据清理；
  自检里要断言导出 JPEG 无 APP1 段。
- 分期：0 外壳 → 1 取文字 → 2 打码 → 3 翻译 → 4 表格（第 4 期先不实施）。

尚未开工，等用户确认排期后从第 0 期开始。

改动的关键点（下次接着做第 1 期的入口）：

- `web/app.js` 的视图路由从"二元布尔"（`toImages = key !== 'edit'`）改成三视图：
  新增 `TEXT_KEYS`、`viewOf(key)`、`paintView(name)`、`goView(name, key)`。
  `WBShowImages` 与新的 `WBShowText` 都只是 `goView` 的薄包装。
  **`goView` 只在用户主动切换时写 hash**（replaceState）；由 URL 触发的
  `applyViewRoute` 不写 —— 否则刷新一次就多出一个 `#edit`。
  就绪信号沿用 `wb-images-ready` 那套，新增 `wb-text-ready`。
- `web/shell.js`：NAV 加 `text`（图标复用 `#i-shield`）；`LEGACY` 表扩成**通用别名表**，
  把 `text-copy/text-mask/text-translate` 也映射到 `text`，这样模式深链下侧栏高亮
  仍然对。以后有子模式就加这里，不用新机制。
- `web/text.js`：三个模式 `copy / mask / translate`，hash 分别是
  `#text-copy / #text-mask / #text-translate`，裸 `#text` 落到默认模式且**不把 hash
  改写成 #text-copy**（否则分享出去的地址会悄悄变样）。`WBText.showKey` 与
  `WBShowText` 互为回喊，goView 不会再回调 showKey，所以不会死循环。
- `web/index.html`：`?v=` 3.6 → **3.7**；新增 `#viewText`（`.view-embed` +
  `.tw-top` 顶栏 + 三个 `.tw-panel`）。样式在 `text.css`，
  `#viewText.on` 的高度链路照抄 `#viewImages.on`（`.view-embed.on` 是 flex，
  内部容器必须自己撑满，否则 0×0）。
- `tools/probe_views.mjs`：`viewState` 加三个视图与三个面板的可见性；
  `clickNav` 的 expect 用 `VIEW_ID` 表映射（原来只认 edit/images 两个）；
  新增 [2c] 模式切换与 [5] 里的三条模式深链断言。

坑：`.tw-panel` 一开始想直接复用 `.view` 类，但 `image.css` 里 `.view{display:flex}`
是无作用域的，虽然 `[hidden]{display:none !important}` 能压住它，但耦合太深，
最后用独立的 `.tw-panel`。`[hidden]` 的 `!important` 在 shell.css 与 style.css 里都有。
