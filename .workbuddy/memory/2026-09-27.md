## 修复：WorkBuddy 会话内 Git Bash 的 PATH 缺失（ls/dirname/head 全不可用）

### 现象
会话内 Bash 工具报 `dirname: command not found` / `ls: command not found`，
`head`/`tr`/`grep` 同样缺失，导致常规命令无法执行。

### 根因
WorkBuddy 自带 PortableGit 在
`C:\Users\35310\.workbuddy\binaries\PortableGit\versions\1.2.0`
- coreutils（`ls`/`dirname`/`head`…）在 `<root>\usr\bin`
- `git.exe` 在 `<root>\cmd`

但这两个目录**既不在系统 PATH（机器级/用户级都没有），WorkBuddy 启动 bash 时也没主动追加**，
于是会话 PATH 里只有 node/python + 系统 PATH，Git Bash 的 coreutils 全部落空。

### 连带影响（重要）
WorkBuddy 通过 `BASH_ENV` 注入
`D:\Programs\WorkBuddy\resources\app.asar.unpacked\cli\vendor\shim\shell-runtime-bash-env.sh`
该脚本第 3 行就调用 `dirname`，因此**整个脚本静默失败**，它负责加载的 safe-delete 保护
（`safe-bin/rm` 等）实际未生效 —— 表现为 `safe_delete_main: command not found`。
即 PATH 坏掉期间，`rm` 等删除操作处于无防护状态。

### 修复
把两条追加到**用户级 Path**（只新增，未删除任何原有条目）：

```
C:\Users\35310\.workbuddy\binaries\PortableGit\versions\1.2.0\usr\bin
C:\Users\35310\.workbuddy\binaries\PortableGit\versions\1.2.0\cmd
```

修改前用户级 Path（如需回滚）：
```
C:\Users\35310\AppData\Local\Microsoft\WindowsApps;C:\Users\35310\.dotnet\tools;C:\Users\35310\AppData\Local\Programs\Microsoft VS Code\bin
```

**改完必须重启 WorkBuddy** —— 会话 PATH 是主进程启动时的快照，当前会话不生效。

### 踩到的工具限制（下次别绕远路）

## 优化 Cloudflare Workers 版代码（共 7 处）

### P0 真实缺陷
1. **`gen.js` extractError 丢弃上游错误详情**
   Python 版 `_extract_error` 返回元组 `(msg, detail)` 两个值都用上，我只返回了 msg，
   上游的具体原因（如 "insufficient balance"）全部丢失。改为返回 `{ message, detail }`，
   两处调用点同步使用。
2. **`store.js` 模块级缓存无 TTL**
   KV 本身最终一致（读最多落后 60s），但缓存永不过期 → isolate 在**整个生命周期内**
   都用陈旧数据：后台改了中转站 key，落到该 isolate 的请求可能几小时都用旧 key。
   加 `CACHE_TTL_MS = 30_000`，写透时续期。

### P1 配置失效 / 行为偏差
3. **`MAX_UPSTREAM_TIMEOUT` 写在 wrangler.toml 却没人读** —— 纯摆设。
   现在 `image.js` 读取它作为上限，客户端可要求更短、不能超过它。
4. **`ensureSeed` 每个请求都执行**（连静态资源也触发）。
   Python 版是启动时调一次 `ensure_seed()`，Worker 没有启动钩子 → 改为按 KV 记录，只播种一次。

### P2 健壮性
5. `resp.js` 顶部注释与实现不符（说"完全复刻对象形状"，但无痕改字那路是字符串）→ 已澄清两种形状。
6. 安全头补齐：API 加上 `X-Frame-Options: SAMEORIGIN`；
   `index.js` 出口统一收口为 `finalize()`，静态资源与页面路由也带上安全头（此前只有 API 带）。
7. `store.js` 缓存改为按 KV 分桶（`WeakMap<KV, Map>`），避免一个 isolate 里多套 KV 串台。

### ⚠️ 测试抓到我自己的两个疏漏（值得记住）
- 新增的超时断言发现：我在 `gen.js` 保留的硬编码**下界** `Math.max(..., 10)`
  把部署方设的 1s 上限顶回了 10s —— **加下界会架空上限**，钳制逻辑必须两头看。
- `ensureSeed` 用了模块级布尔量，而缓存已按 KV 分桶 → 两者不一致，播种状态跨 env 泄漏，
  导致 [5]「种子+新建=2 条」断言失败。改为 `WeakSet` 按 KV 分桶后一致。

## 浏览器端 OCR 可行性验证（PoC）

用户问：「调用模型必须用 OpenCV 和 ONNX Runtime 吗，能让模型缓存在浏览器里、网页调用浏览器的吗」
→ 结论：**可行**，且已实测通过。产物在 `wasm-poc/`，报告 `wasm-poc/REPORT.md`。

### 关键事实
- 不是「不用这两个库」，而是**换成浏览器 WASM 版**：
  ONNX Runtime → `onnxruntime-web`；OpenCV → `opencv.js`
- **`cv.inpaint` 在 opencv.js 官方构建里可用**（photo 模块默认包含），
  `INPAINT_TELEA` / `INPAINT_NS` 都在 → 擦除环节有直接对应物
- 模型**零下载**：直接复制 `~/.workbuddy/binaries/python/envs/default/Lib/site-packages/
  rapidocr_onnxruntime/models/` 下的 3 个 onnx（det 2.4MB / rec 11MB / cls 0.57MB），
  字典内嵌在 rec 模型的 metadata（`character`，`splitlines()` 解析）
- **真正的坑是字体**：`app/fonts.py` 扫描 `C:\Windows\Fonts`，
  浏览器没有枚举系统字体的 API（隐私硬限制）→ 必须托管字体文件

### 复刻要点（踩过的坑）
- **RapidOCR 全程用 BGR**：`cv2.imread` 后直接归一化，mean/std 虽按 RGB 写但喂的是 BGR。
  按 RGB 复刻会全错
- `unclip` 用 pyclipper，浏览器没有 → 用**几何扩张精确等价替代**
  （输入恒为 minAreaRect 矩形，偏移后外接矩形恰为 (w+2d, h+2d)）；
  已用对照实验证明这个替换**不影响最终结果**
- Python `round()` 是银行家舍入，JS `Math.round` 不是 → 写了 `pyRound()`
- `np.rot90` 是逆时针，用 `transpose + flip(0)` 复刻（不是 `ROTATE_90_CLOCKWISE`）
- CTC 置信度是 `np.mean(conf_list + [1e-50])`，**分母 n+1**

### 验证结果
- `samples/test_card.png`(9 框)：**文本 9/9 一致**，坐标最大偏差 2.0px
- `samples/out/ui_11_edit_loaded.png`(64 框)：49/64，差异为标点/空格/全半角/临界字，
  且有 1 处是 **Python 端反而错** → 双向噪声，非单边劣化
- 对照实验：把 Python 的 unclip 也换成几何扩张，结果一字未变
  → **剩余差异来自 WASM 与原生 ONNX Runtime 的浮点差异，无法消除**

### 真浏览器才暴露的问题（Node 验证发现不了）
- `ort.env.wasm.wasmPaths = "vendor/"` 在浏览器里报
  `Failed to resolve module specifier` —— ort 用动态 `import()` 加载 wasm glue，
  **必须是绝对 URL**，不能是裸路径。改用 `new URL("vendor/", document.baseURI).href`

### 环境备注
- 没有 browser-use（未安装）、系统无 Chrome，用 **Edge headless + `--dump-dom` / `--screenshot`**
  做真实浏览器验证，配合 `--virtual-time-budget` 等待异步完成
- `@techstark/opencv-js` 在 Node 里导出的是 **Promise**，需 `await`
- ort 在 Node 里 `wasmPaths` 需要 `file:///` 协议前缀

## 下午：Cloudflare 版推倒重来 —— 模型缓存进浏览器

### 用户决策
- 范围：**全量做到重绘**（不止 OCR，含擦除 + 重绘）
- cloudflare 那套「反代回本机 Python」**彻底删掉**，Worker 只留静态托管 + 图片生成

### 方案定调
模型不再是服务端的事，而是**静态资源**：40MB 的 onnx/wasm/opencv.js 由
**Service Worker + Cache Storage** 缓存在浏览器里，网页直接调用本地缓存推理。
改字全流程（识别→样式→擦除→重绘→导出）都在浏览器完成，服务端只剩
「静态托管」和「必须保密的图片生成 API」。

选 Cache Storage 而不是 IndexedDB 的**决定性理由**：
`onnxruntime-web` 是从 URL 加载模型的，SW 拦一道之后
`InferenceSession.create('/assets/models/x.onnx')` **一个字都不用改**；
走 IndexedDB 得先把 11MB 模型读成 ArrayBuffer 再喂进去，多一次全量内存拷贝。

### 新增文件
- `web/sw.js` —— SW，只管 `/assets/` 前缀（其余一概放行，避免缓存 API 响应）
- `web/modelstore.js` —— 账本：manifest 说该有什么，Cache Storage 说存了什么
- `web/engine/runtime.js` —— opencv.js + ort 的加载与就绪等待
- `web/engine/ocr/` —— det.js / rec.js / engine.js（从 wasm-poc 搬，base 改 `/assets`）
- `web/assets/` —— 模型 + vendor + 字典（39.45MB，gitignore）
- `tools/gen_assets_manifest.mjs` —— 生成 manifest，版本号从 sw.js 抠，避免两处手写对不上
- `tools/serve_dev.mjs` —— 本地静态服务器（.wasm 必须 application/wasm）
- `tools/verify_cache.mjs` —— 真实 Edge + CDP 验证缓存闭环

### 踩到的两个时序坑（都是"看起来对、其实没生效"的类型）
1. **首次访问时 SW 还没接管页面** → fetch 不经过 SW 的 handler → 下的模型**根本不会进缓存**。
   靠 `clients.claim()` 让当前页立刻受控，页面侧要 `await controllerchange` 再开始下载。
2. **`cache.put` 是异步的**（挂在 waitUntil 上）→ "浏览器读完响应" ≠ "已落盘"。
   最大的识别模型 10.2MB 读完后仍在写，立刻查状态会看到"少一个文件"进而重复下载。
   → `ModelStore._awaitPersisted()` 轮询确认。

### 验证结果：`node tools/verify_cache.mjs` **9/9 通过**
- 首次访问模型未缓存 → 预热 39.45MB 全部入缓存
- 重载页面后：**SW 返回 9 个请求，走网络 0 个**，全量重取仅 6ms
- 断网后 8/8 资源仍可读（全部来自缓存）
- 本地推理：识别 9 个文本块，2669ms（与 Python 基线框数一致）

### ⚠️ 最大的坑：opencv.js 的 Mat.data 不是类型化视图
`CV_32F` / `CV_32S` 的 `mat.data` **不是** Float32Array / Int32Array，
而是指向同一块堆内存的 **Uint8Array 字节视图**。
直接 `dd[i]` 读拿到的是字节而非距离/标签值 —— 数字看着"有值"，其实全错。

引发的连锁症状：
- 笔宽算出 **270px**（实际应 ~5px）
- 连通域 area 全乱 → `keepComponents` 失效 → 掩膜吞进相邻行/背景
  → 字色反推成**背景色**（白色）→ 改完的字在浅底上看不见

正解：`mat.data32F` / `mat.data32S`。已在 `cvutil.grayData` 做类型分派兜底。
**以后凡是 CV_32F/CV_32S 的输出，一律走 data32F/data32S。**

### 诊断方法（值得复用）
页面主线程被某个同步循环卡死时，常规 `Runtime.evaluate` 全部超时，
完全看不出停在哪。有效做法：

1. **在关键位置 `console.log` 打点**，再用 CDP 的 `Runtime.consoleAPICalled`
   实时接收 —— console 消息是即时推送的，主线程卡死之前打的点都收得到，
   **最后一条就是元凶**。
2. 诊断脚本要**每步一个独立 CDP 调用**，别用页面内一个大循环 ——
   一处卡死会把后面全部带崩（连"创建一个 canvas"都会假超时，误导排查方向）。
3. 断言脚本要收集 `Runtime.exceptionThrown` / `console.error`，
   否则模块加载失败只表现为"等待超时"，看不出原因。

待查：真实页面路径下 `/api/apply` 报"重绘 0 处"，而 engine-test 页面下同样流程成功。

### ⚠️ 第二个坑：带缓存的 Mat 不能在外面 delete
`renderInkMask` 把字形掩膜缓存进 `_maskCache`，但 `matchFamily` 里对返回值调了
`rm(cand)` —— 第一次调用就把**缓存对象**释放了。下次同 key 命中拿到已释放的 Mat，
访问时报 `cannot call emscripten binding method Mat.data getter`。

症状格外隐蔽：**只在"同一段文字被渲染第二次"时才炸**。
所以 preview 先跑、apply 后跑必失败；两者调换顺序则通过 ——
顺序一变现象就变，极容易被误判成"时序问题"或"会话失效"。

正解：**缓存对象的所有权归缓存，外面一律不许 delete**；
改由 `putMaskCache` 做容量淘汰（每个 mask 约 1MB，不淘汰会吃光 emscripten 堆）。

### ⚠️ 第三个坑：grayData 返回的是内部缓冲引用，不是副本
`grayData(mat)` 在 Mat 连续时**直接返回 `mat.data`**（内部缓冲）。
`style.analyze` 里"前景取反得背景掩膜"那一步就地改了它 ——
等于把 `fgMask` 自己改成了背景掩膜。之后所有基于 fgMask 的度量全部拿到"背景"：

- 字色取成**背景色**（白底黑字 → 取到白色 → 改完的字在浅底上完全看不见）
- 笔宽虚大（26px，实际约 6px）
- 字号虚大（墨迹 bbox 撑满整个 ROI，91px vs 实际约 62px）

三个症状同时出现，太容易被当成三个独立问题分别去查。
正解：**要就地改就先拷一份**。已在 `cvutil.grayData` 注释里写明这个陷阱。

### ⚠️ 第四个坑：crop 出来的 Mat 不连续
`dominantColor` 用 `bgrMat.data` 按 `i*3` 平铺索引取色 —— 但 crop / clone 出来的 Mat
实测 **`isContinuous()` 为 false**，而 `data` 长度看着又是精确的 rows×cols×3，
于是索引整体错位。症状：掩膜明明罩在文字上（像素数也对），取色却取到背景，
白底黑字 → 字色判成**白色** → 改完的字在浅色底上完全看不见。

**这四个坑的共同特征**：都不抛异常、数字看着都"有值"，只是全错。
现在 `cvutil.planeData()` 统一保证连续，`grayData` / `matToImageData` / `matToRgba`
全部改走它；`dominantColor` 改为逐行取 `ptr`。

## 部署上线 + 四个线上问题（第二轮）

### 部署结论

- **线上地址：`https://ps.ysw69.dpdns.org`**（自定义域名，用户自己绑的）
- `*.workers.dev` **在国内不可用**：实测本机 `net::ERR_CONNECTION_TIMED_OUT`，
  阿里 DoH 返回 `128.242.250.155`（非 Cloudflare 网段）→ DNS 污染。
  自定义域名走 Cloudflare 则正常。已把 routes 写进 `wrangler.toml`，
  免得后续 deploy 覆盖掉 Dashboard 上手动加的绑定。
- **线上验证 17/17 通过**（`tools/verify_online.mjs`，真实 Edge 直连生产域名）：
  首访/预热 39.45MB/重载后 SW 命中 14 个·走网络 0 个/断网 8-8/识别 9 块/
  样式（字号 57·字色 rgb(32,32,36)）/擦除重绘/出图。
- 沙箱代理白名单**允许** `ps.ysw69.dpdns.org`（curl 可直连），排障方便；
  但 `*.workers.dev`、`1.1.1.1/dns-query`、`r.jina.ai` 都被 502 拦。

### 四个问题的根因

1. **后台登录 500** —— Workers 的 WebCrypto **PBKDF2 上限 10 万轮**，
   Python 版用 12 万 → `derive()` 直接抛错 → 500「服务端内部错误」。
   改：`PBKDF2_ROUNDS = 100_000` 且**轮数随记录存**（`rounds` 字段），
   校验按记录里的轮数复算；超上限的旧记录判为 `legacy`，
   `/api/admin/status` 直接返回 `needs_setup:true` → 前端给设置表单，
   不会让人对着「密码不正确」发懵。密码已重置为 `yyds1234`。
   ※ fixtures 新增 `hash_100k`（Python 现算），compat 14/14。
2. **「无法连接后端服务」+ 字体列表为空** —— `app.js` 初始化用了**裸 fetch**
   取 `/api/health`、`/api/fonts`，绕过本地引擎；CF 版没这两个路由 →
   空响应 → `r.json()` 抛 "Unexpected end of JSON input"。
   改：新增 `apiGet()` 本地优先 + `readJson()` 把空体/非 JSON 说成人话。
   **`/api/export` 也是裸 fetch，同样必然 404** → 已补 `LocalApi.exportBlob()`
   （canvas.toBlob，png/jpg/webp，JPEG 先铺白底），并在 `boot.js` 暴露。
3. **图片生成超时** —— 实测一次 1024×1024/1 张 **用时 57.7s**，
   原来上限 60s 正好卡在边缘，所以时好时坏。
   改：`MAX_UPSTREAM_TIMEOUT` 60 → **90**（贴 Cloudflare 边缘约 100s 的响应上限，
   再高就变 524）；前端显式传 `timeout`，并把 524/522 与 504 分开解释。
4. **字体导入** —— 原来打 `/api/fonts/upload`（服务端），CF 版没有该路由。
   改：**全部搬到浏览器**。
   - `FontRegistry` 新增本机字体仓库：导入用 FontFace 注册 + 字节存
     Cache Storage（`wb-ps-fonts-v1`，键名 `/__local-fonts__/<file>`），
     索引存 localStorage，刷新后自动恢复。
   - `scanLocalFonts()` 走 Local Font Access API（`navigator.queryLocalFonts`），
     只登记字族清单，**字节在真正要用时才按需读**（几百个字体全读进内存太重）；
     `LocalApi._primeFonts()` 在 preview/apply 前把候选池与手选字族预热好，
     否则 canvas 会静默回退到默认字体（度量全错但不报错）。
   - `all()` 顺序：托管 → 导入 → **精选探测** → 扫到的本机字体。
     机扫的几百个字族必须排在精选清单之后，否则自动匹配会先撞上
     Algerian 这类装饰体，把拉丁文匹配得乱七八糟。
   - 界面新增「本机字体」按钮；「导入字体 / 重新扫描」的 tooltip 说明不上传。

### 坑（第五个同类型：看着成功、其实全错）

`user_count` / `families` 这些字段名前端早就在用，而本地 API 当时返回的是
`{fonts, count}` —— 字段对不上不会报错，只会静静显示成空列表。
**接线时字段名要对着调用方核，别对着自己的实现核。**

### 第二轮验证中又抓到的三个问题

1. **初始化竞态（这是"无法连接后端服务"真正的根因）**
   `boot.js` 是 `<script type="module">`（延迟执行），`app.js` 是普通脚本会**先跑**。
   于是初始化那一刻 `window.WBLocal` 还不存在，所有接口被判成"本地不处理"，
   一股脑发到服务端 → CF 版全是 404。
   轨迹探针抓到的铁证：`[2.6s] → GET /api/health` / `[2.8s] ← 404`。
   改：`localFacade()` 等门面出现（最多 20s）+ 监听 `wb-local-ready` 补一次探测
   + 引擎下载中不再报"无法连接后端服务"，改为显示真实进度。
   **同类风险**：任何"普通脚本 + 延迟模块"的组合都要留意执行顺序。

2. **`queryLocalFonts` 挂在 `window` 上，不是 `navigator`**
   写成 `navigator.queryLocalFonts` 永远 undefined，表现为"当前浏览器不支持"，
   而浏览器其实完全支持（Edge 153 实测 `window` 上有、`navigator` 上是 undefined）。
   另外两条约束：必须安全上下文；**必须由用户手势触发**，且页面 `visibilityState`
   不能是 hidden（否则 `SecurityError: Page needs to be visible`）。
   ※ 无头浏览器里这个 API 恒不可用，别用无头去判断"浏览器支不支持"。

3. **同步失败但部署照跑**
   `sync-assets.mjs` 的 `rm -rf public` 会被沙箱的安全删除机制拦截（有时是
   批量确认阈值 50 个）。如果和 deploy 串在一条命令里，就会出现
   "同步失败、部署照样成功、线上留着旧文件"。
   **部署后必须核对线上文件内容**：
   `curl -s <域名>/static/xxx.js | grep -c "<本次改动的特征符号>"`。
   单独执行 sync 时沙箱通常放行（会提示 Sandbox bypassed）。
