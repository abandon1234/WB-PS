## 文字工坊：从「三页面」改成「一页 + 三功能键」

用户给了一张截图，说「取字、打码、翻译，点一个就切换一个页面。能不能做成一个页面，
取字、打码、翻译三个做成功能按键」。原实现确实是三个 `<section>` 各带一整套
`tw-stage`（画布 + 缩放 + 状态条）+ 一个 aside，切模式等于换掉整块 DOM，
而且三个模式各有自己的 `file`，切过去图就没了、得重选。这是"换页感"的真因。

### 改法（web/index.html + text.js + text.css）

- **HTML**：三个 panel 合成一个 `#viewTextMain`，里面**一套共用 stage**
  （`twCanvas / twImg / twOverlay / twMaskCv / twMarquee / twZoom / twStatus /
  twName / twMeta / twDrop / twPick / twView / twHint`）+ 三个
  `<aside class="tw-side" data-side="copy|mask|translate">`。面板显隐从
  `MODES[].panel`（三块 section）改成 `data-side` 匹配。
- **JS**：`COPY_ELS / MASK_ELS / TR_ELS` 三组映射合成一个 `ELS`；
  三个 `createZoom` 实例合成一个 `stageZoom`（`onChange` 按 `S.mode` 分发，
  只有打码要重绘遮盖层）。`wireCommon` → `wireStage()`，只挂一次。
- **文件共享**：新增 `CUR`（file / name / url / fittedOnce）。三模式里的
  `file / name / objectUrl` 字段全删，改为读 `CUR`。选图统一走 `openFile()`。
- **按需补跑**：`LOADED = {copy, mask, translate}` 记「这个模式算过哪个文件签名」，
  `ensureLoaded(mode)` 只在没算过时跑。取文字与打码共用 `detectOnce`
  （加了 **in-flight 去重**：检测跑到一半切模式，两边会同时来要同一张图的结果）。
- **跨模式异步守卫**（共用一套 DOM 之后必须做，否则后台跑完的任务会污染前台）：
  - `setStatusFor(mode, ...)`：只有当前模式在前台才写状态条
  - `renderMaskOverlay / paintMasks / renderCopyOverlay` 开头判 `S.mode`
  - `wireMarquee` 的 pointerdown 判 `S.mode === 'mask'`
  - `switchTrView` 只在 `S.mode === 'translate'` 时才换 img.src；离开翻译模式
    `ensureSourceImage()` 切回原图
  - 每个模式记自己的 `meta`（尺寸+耗时），`paintMeta()` 按当前模式显示
- **CSS**：`.tw-side:not([hidden])` 加 0.16s 淡入（带 `prefers-reduced-motion` 兜底）。
- index.html 的 `?v=` 5.0 → 5.1；`tools/probe_views.mjs` 里的旧 id 同步改了。

### 踩到的坑

沙箱里探针报 `chrome-error://chromewebdata/`、诊断出 `location.href` 是
chrome-error —— 第一反应会以为是沙箱拦了回环，**实际是后台起的本地服务被回收了**
（`&` 起的进程活不过那次 bash 调用）。用 `run_in_background` 起服务才是活的。
判据：`curl` 若返回 502 / 000，先确认服务再怀疑沙箱。

### 顺带修掉的一个本地 dev bug：`.mjs` 的 MIME

跑全量 `probe_views.mjs` 时 [2e] 报「本地引擎无错」失败：
`no available backend found. ERR: [wasm] TypeError: Failed to fetch dynamically
imported module: http://127.0.0.1:8000/assets/vendor/ort-wasm-simd-threaded.mjs`

根因**不是**这次重构，而是 `app/main.py` 的静态服务：Python 的 `mimetypes`
不认识 `.mjs`，uvicorn 把 `ort-wasm-simd-threaded.mjs` 按 `text/plain` 发出，
浏览器的 ES module 加载严格校验 MIME，直接拒收 —— 所以**本地 dev 下浏览器端
引擎根本起不来**（线上 Cloudflare 有自己的 MIME 表，所以没暴露）。
`app/main.py` 挂载静态目录前显式注册：

```python
mimetypes.add_type("text/javascript", ".mjs")
mimetypes.add_type("application/wasm", ".wasm")   # instantiateStreaming 也认这个
```

判据：`curl -I .../x.mjs` 应返回 `text/javascript`，`.wasm` 应返回 `application/wasm`。

### 连带发现：SW 会把「错的 MIME」永久锁死

修好服务端 MIME 后，探针**仍然**报同样的错。两个原因：

1. `sw.js` 是 cache-first，且 `MANAGED_PREFIXES = ['/assets/']` 把 `.mjs / .wasm`
   也接管了 —— 存下响应时连 `Content-Type` 一起存，之后永远从本地回，
   **服务端改对了也救不回来**。
   → 改 `isManaged()`：`.mjs / .wasm` 不接管，交给 HTTP 缓存（它们不大，
   本来也不需要 SW 这一层）。
2. Edge 的**磁盘 HTTP 缓存**：服务端返回 304，浏览器就继续用带旧 MIME 的本地副本。
   清掉 `<profile>/Default/Cache` 后才真正生效（模型缓存在 `Service Worker/CacheStorage`，
   两处分开，删 HTTP 缓存不影响模型）。

判据：以后改静态资源的 MIME，光 `curl -I` 看服务端**不够**，还要考虑 SW 与浏览器两级缓存。
