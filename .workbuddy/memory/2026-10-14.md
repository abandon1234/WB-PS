### 顺带修掉的一个本地 dev bug：`.mjs` 的 MIME

跑全量 `probe_views.mjs` 时 [2e] 报「本地引擎无错」失败：
`no available backend found. ERR: [wasm] TypeError: Failed to fetch dynamically
imported module: http://127.0.0.1:8000/assets/vendor/ort-wasm-simd-threaded.mjs`

根因**不是**这次重构，而是 `app/main.py` 的静态服务：Python 的 `mimetypes`
不认识 `.mjs`，uvicorn 把 `ort-wasm-simd-threaded.mjs` 按 `text/plain` 发出，
浏览器的 ES module 加载严格校验 MIME，直接拒收 —— 所以**本地 dev 下浏览器端
引擎根本起不来**（线上 Cloudflare 有自己的 MIME 表，所以没暴露）。
`app/main.py` 挂载静态目录前显式注册：

```python
mimetypes.add_type("text/javascript", ".mjs")
mimetypes.add_type("application/wasm", ".wasm")   # instantiateStreaming 也认这个
```

判据：`curl -I .../x.mjs` 应返回 `text/javascript`，`.wasm` 应返回 `application/wasm`。

### 连带发现：SW 会把「错的 MIME」永久锁死

修好服务端 MIME 后，探针**仍然**报同样的错。两个原因：

1. `sw.js` 是 cache-first，且 `MANAGED_PREFIXES = ['/assets/']` 把 `.mjs / .wasm`
   也接管了 —— 存下响应时连 `Content-Type` 一起存，之后永远从本地回，
   **服务端改对了也救不回来**。
   → 改 `isManaged()`：`.mjs / .wasm` 不接管，交给 HTTP 缓存（它们不大，
   本来也不需要 SW 这一层）。
2. Edge 的**磁盘 HTTP 缓存**：服务端返回 304，浏览器就继续用带旧 MIME 的本地副本。
   清掉 `<profile>/Default/Cache` 后才真正生效（模型缓存在 `Service Worker/CacheStorage`，
   两处分开，删 HTTP 缓存不影响模型）。

判据：以后改静态资源的 MIME，光 `curl -I` 看服务端**不够**，还要考虑 SW 与浏览器两级缓存。

### 关键坑：给 `WBLocal` 打桩会被 `boot.js` 顶掉（**踩了一整轮**）

探针最初用 `Page.addScriptToEvaluateOnNewDocument` 在文档创建前预注入
`window.WBLocal = { handle }`。结果 analyze 打不到桩上：

- 现象一路变化：先 `analyze×2` → 改成文档创建前注入后仍 `×2` → 又变成
  `analyze×0 但 items=2` → 最后（冷 profile）**彻底卡在「正在识别…」不动**。
- 真因：`web/engine/boot.js` 是 `<script type="module">`（延迟执行），
  它在**文件末尾直接 `window.WBLocal = {...}` 整体覆盖**，把预注入的桩顶掉；
  于是请求落到真引擎上，真的去下 40MB 模型。
- 老探针 `probe_text_onepage.mjs` 之所以没这个问题，是因为它在**页面加载完之后**
  才 `cdp.evaluate(STUB)` —— 等于"后覆盖"，恰好躲开。但那个时序本身是脆的。

修法（已固化进 `probe_edit_panes.mjs`，README 也写了）：

```js
const stub = { ready: true, progress: null, async handle(url, body) {...} };
Object.defineProperty(window, 'WBLocal', {
  configurable: true, get: () => stub, set: () => {},   // boot.js 的赋值落空 setter
});
window.requestIdleCallback = () => 0;   // 掐掉 boot.js 的空闲预热
```

**为什么还要关 `requestIdleCallback`**：boot.js 的预热是 `requestIdleCallback(() =>
ensureEngine(...))`，**直接调内部函数、绕不过 `window.WBLocal`**，桩拦不住它 ——
不关的话每轮都会去注册 SW、读 manifest、拉模型。只有 boot.js 用 rIC，关它无副作用。

判据：打桩类探针若出现「脚本挂在某个 busy 状态再也不动」，先怀疑桩被覆盖。

## 第三轮：修「生成结果图和改的不一样」—— UI 与引擎的改动判据裂了

用户给两张截图：编辑界面那一行是「聚缘快捷宾馆」，结果图是「聚缘快捷宾馆1」，
说"生成结果图和改的不一样"。

### 定位（像素级，没靠猜）

从截图里量出来的硬事实：

- 图A（编辑态）该行暗像素 x 745..844，选中框（`#60a5fa`）x 734..855、
  右竖边落在 842..848；**x 849..853 是纯白**
- 图B（结果图）该行暗像素 736..853，8 个字符段，末段 846..853 是孤立的「1」
- 图A 状态卡写「结果已生成 · 改动 0 处」

### 逻辑闭环

`stats.rendered` 只数 `replace`/`insert`（`pipeline.py` 与 `engine/index.js` 同款），
`0 处` ⇒ `targets` 空 ⇒ `applyEdits` 走 `imageBgr.clone()` ⇒ **结果图 ≡ 原图**。
所以**原图本来就是「聚缘快捷宾馆1」，OCR 漏了末尾的 1**。

那编辑界面为什么只有 6 字？因为它不是原图 —— UI 贴了本地预览补丁，而
**补丁的擦除范围是 `rect` 外扩**（`erase.js`：`pad = clamp(round(h*0.9), 8, 48)`，
本例 h≈24 → pad≈22）→ 框外的「1」被一并擦掉。

UI 为什么会贴补丁？因为 UI 的 `isChanged` 与引擎的 `isDirty` **判据不同**：

- UI：`if (e.text !== undefined) return true;` + 样式字段"非空/非默认即算改"
- 引擎：必须与 `item.text` / `item.style.xxx` 真的不同

### 修法：判据只留一份

- 新建 `web/engine/dirty.js`（`isDirty` 唯一实现，注释写清来龙去脉）
- `engine/index.js` 删掉本地实现，改静态 import
- `app.js` 的 `isChanged` 改动态 `import('./engine/dirty.js' + ?v=)`；
  `restoreWorkspace()` 开头 `await DIRTY_READY`（否则恢复流程会按错口径排补丁）
- `index.html` 版本号 5.2 → 5.3

### 探针加固（做了回退验证）
