# 图片文字处理与生成工具

一个统一的「图像工作台」：三个页面共用同一套侧边栏外壳，导航直达各功能模块。

| 模块 | 页面 | 说明 |
|---|---|---|
| **无痕改字** | `/` | 扫描图片文字、还原样式、原位无痕替换 |
| **图像工坊** | `/image` | 调用中转站 gpt-image-2 生成图片（文生图 / 多参照图） |
| **作品库** | `/image#projects` | 生成与保存的图片，全部缓存在浏览器本机 |
| **后台管理** | `/admin` | 中转站地址与 API Key 配置（需登录，密钥不下发前端） |

## 统一外壳

`/` 与 `/image` 共用 `web/shell.css` + `web/shell.js`：

- **侧栏一处定义**，导航项就是普通 `<a href>`，跨页跳转与浏览器前进后退天然可用
- 分组：`图片工具`（无痕改字 / 自由生成 / 图像融合 / 人物写真 / 商品图生成）、
  `资源`（作品库，带实时数量徽标）、底部本机占用条 + 后台入口
- **深链**：`/image#combine` 直接选中「图像融合」工具，`/image#projects` 直达作品库
- 图标雪碧图由 `shell.js` 统一注入，各页面不再各抄一份
- 侧栏折叠状态存 `localStorage`，窗口窄于 1100px 时**首次自动折叠**，之后完全听用户的

`/admin` 刻意不引入外壳——它是独立外观，一眼能看出是「管理区」。

### 外壳上修掉的两个 bug

**① 侧栏折叠后展不开（会把自己锁死）**

折叠态下品牌行还是横排（logo 27px + 间距 + 按钮 26px），而侧栏只有 62px 宽，
折叠按钮被压成 **0 宽**并被 `.sb-brand` 盖住 —— `elementFromPoint` 命中不到它。
用户点一次「收起」就再也收不回来，只能清 localStorage。
另外窄屏的媒体查询**无条件**把侧栏压成 62px，连类名都不看，让这个问题更隐蔽。

改法：折叠态品牌行改竖排（logo 在上、按钮在下，28×28 保证命中面积）；
把「强制折叠」从媒体查询移进 JS，只在没有用户偏好且窗口 < 1100px 时自动折叠一次；
折叠按钮的 `title`/`aria-label` 随状态在「收起/展开侧栏」间切换。

**② 尺寸/数量菜单关不掉，一直浮在界面上**

`closePop()` 只把遮罩 `#popWrap` 设成 `hidden`，而 `#pop` 面板是 **`document.body` 的子节点**
（不是遮罩的子节点），`position: fixed` 又不受 `body` 的 `overflow:hidden` 影响 ——
于是遮罩没了，菜单还留在屏幕上；只有下次打开别的菜单才会被 `openPop` 里的
`old.remove()` 顺手清掉。改成把面板挂进遮罩内部，隐藏遮罩即隐藏菜单；
定位也改成先量尺寸再摆位，上方放不下就翻到下方，都不行再夹进视口。

两个 bug 都固化成了断言，见 `node tools/ui_shot.js --verify`。

# 模块一：无痕改字（图片文字处理）

扫描图片中的文字，识别其**内容与位置**，还原**字体、字号、颜色、粗细**，
并在原位置做**无痕修改替换**——改完看不出动过手脚。

## 工作区断点续做

切到「自由生成」再切回来，编辑状态不会丢。实现分两层：

- **本机持久化**：`web/workspace.js` 把工作区落到浏览器 IndexedDB，拆两张表——
  `meta` 放轻量状态（session_id / 识别结果 / 改动 / 视图），每次编辑都写；
  `image` 放原图字节，只在换图时写。混在一张表里的话，每敲一个字都要重写几 MB 原图。
- **服务端会话复用**：`GET /api/session/{id}` 把仍在内存里的识别结果原样读回
  （**不重跑 OCR**）。会话还在就直接复用；服务重启后会话没了，
  就用本机存的原图重新识别，并按「item id → 原文 + 位置」两级兜底把改动映射回去。

改动样式回填走 `POST /api/preview-batch` 一次拿全补丁，
而不是 N 处改动发 N 次请求——顺带把 `applied` 区域填好，之后单条「重置」才有依据。

落盘时机：编辑一轮结束（预览返回）立即写；另有 400ms 防抖兜住连续输入，
再叠加 `pagehide` / `visibilitychange` 收尾，保证跳转前一定写进去。

想主动丢弃时点工具栏的**关闭图片**，会同时清掉本机快照。

## 自定义字体

系统字体之外，可以把**自己的字体**加进来用于替换。

**方式一（推荐）**：编辑面板 → 字体 → **导入字体**，选 `.ttf` / `.otf` / `.ttc`，
立即生效，不用重启服务。已导入的字体在下拉框里带 `★` 前缀。

**方式二**：把字体文件直接拷进项目根目录的 `fonts/`，点 **重新扫描**（或重启服务）。

说明：

- `fonts/` 的优先级**高于系统字体**，同名族会优先用这里的版本
- `.ttc` / `.otc` 是字体集合，内含多个字体会自动逐个登记
- 删除文件后同样需要「重新扫描」才会从列表消失
- 只接受字体扩展名，且落盘前会校验能否被解析，无效文件不会残留
- 字体文件的增删会让扫描目录的 mtime 变化，缓存自动失效，不需要手动清缓存
- `fonts/` 里的字体文件已在 `.gitignore` 中排除，避免把有版权的商业字体分发出去

## 两大核心能力

### 1. 文字识别与定位

- 输出每个文本块的**四点坐标**（可表达倾斜）与**轴对齐矩形**
- 同一行的碎框自动合并成「文本行」，编辑体验与视觉还原都更自然
- 长边超过 2400px 自动降采样加速，坐标映射回原尺寸

### 2. 无痕修改与替换

这不是"盖一块色块再写字"，整条链路有六处针对"不露痕迹"的设计：

**① 样式反推：颜色**
不用平均值（抗锯齿像素会把颜色拉灰）。做法是以背景色为基准，
取偏离最大的那批像素（真实墨迹核心）的众数颜色。

**② 样式反推：字号**
由**墨迹高度**反推，而不是 OCR 框高度（框含 padding，不可靠）。
且不用经验系数——渲染前会**实测**所选字体参考字的字面比例
（例如微软雅黑汉字 0.908、黑体 0.883、Arial 大写 0.717），
因此换字体后字号依然对得上。

**③ 样式反推：粗细 / 背景**
粗细用「笔画宽度 ÷ 墨迹高度」判定（距离变换峰值），不依赖字体元数据。
背景分为**纯色 / 渐变 / 纹理**三类，各自走不同的擦除策略。

**④ 精确掩膜**
用**局部背景图**（形态学开/闭运算估计）做差分，而不是全局阈值——
后者会把渐变背景整片误判成文字。掩膜只保留与目标框重叠的连通域，
避免擦到上下相邻的行。擦除用途关闭连通域去噪，
否则文字顶部的细小抗锯齿碎片会被当噪点剔除，留下淡淡轮廓。

**⑤ 分级擦除 + 残留自检**

| 背景 | 策略 | 原理 |
|---|---|---|
| 纯色 | `fill` | 用紧贴掩膜外圈的真实像素估色后整块填充（不需要羽化，羽化反而造软边） |
| 渐变 | `linear` | 逐列/逐行用掩膜外侧像素做线性外推，取接缝更平滑的方向 |
| 纹理 | `inpaint` | OpenCV Telea / NS 内容修复 |

擦完会**自动检测残留**（框内边缘能量 ÷ 周边背景边缘能量），
偏高就逐轮加大掩膜重擦，最多三轮。

**⑥ 贴合渲染**
- 4 倍超采样绘制后缩回，边缘平滑度接近系统抗锯齿
- 逐字符布局 + 以基线为锚点，跨字体基线一致、支持字距
- 对齐的是**墨迹外接框**而非 OCR 框，消除字体上升/下降部造成的错位
- **清晰度匹配**：原图若经 JPEG 压缩、文字边缘偏糊，按原图锐度对新文字做等量柔化，否则新字会"太锐"而露馅
- **不因原框宽度而改字号**（默认行为）：字变小比"略超出原位置"更容易被一眼看出来，
  而实际场景里文字旁边多半是空白。只有溢出到会盖住相邻内容（超过 1.8 倍）
  才收敛字号，且不低于原字号的 72%。想主动压回原宽度可在面板勾选「过宽时缩字号」。
- 宽度比较一律用**墨迹 bbox**，而不是渲染图层的画布尺寸——图层左右带有约
  0.35×字号的透明 padding，拿画布宽去比会凭空多出几十像素，
  导致"过宽"判断几乎每次都误命中、字号被无故缩小。
- **垂直按底部（基线）对齐**（默认）：阅读时的视觉锚点是基线，按基线对齐最不容易
  看出被改过。若改成居中，新旧文字墨迹高度稍有不同就会把整行推走。
  可在面板切换为居中 / 顶部。
- 墨迹外接框用 **alpha 阈值**测量，而不是 `getbbox()`——LANCZOS 缩放的振铃会在
  字形外围留下极低 alpha 的伪影，`getbbox()` 会把它算进"内容"，
  实测能让墨迹高度虚高 40px 以上，进而把垂直定位整体带偏。

**⑦ 字体与粗细还原（决定"像不像"的关键）**

字体族用**两阶段匹配**：

1. 用「墨迹宽高比 + 墨迹填充率 + 笔画比」从**常用字体白名单**里筛候选
   （不做白名单限制会选中 ITC Bookman 这类"比例接近但字形无关"的冷门字体）
2. 拿**原文字在图中真实的墨迹轮廓**，与候选字体的渲染轮廓做形状 IoU，取最高者

第 2 阶段是必要的：低维特征区分不了 Segoe UI vs Trebuchet MS、
Helvetica vs Calibri（得分几乎打平），而形状 IoU 是拿真实笔画轮廓直接比，能分辨。
注意匹配用的是**原文字**——那才是图里真实存在、可以和模板比对的形状。

笔画粗细做**闭环校准**：渲染 → 用与测量原图相同的口径测笔画宽度 → 补描边 → 再测，
最多两轮。即使字体本身偏细，也能补到与原图一致；若原文字更细，
会尝试切到同族的 Light / Thin 变体。

匹配前会过滤掉**渲染不出该文本的字体**（例如用 Calibri 去画中文）——
否则墨迹度量整体失真（实测会把字号算成 1.7 倍）。

## 密钥是怎么被隔离的

这是本次改动的重点。**任何接口都不会把 API Key 下发给前端。**

1. **两套接口前缀**：生成页只依赖 `/api/image/status` 与 `/api/image/generate`；
   配置类接口全部搬到 `/api/admin/*`，必须登录才能访问。
   原来下发明文 key 的 `/api/image/overview`、`/api/image/providers` **已彻底删除**
   （访问返回 404）。
2. **默认打码**：`config.public_view()` 的 `reveal` 默认值改为 `False`，
   凡是走到 HTTP 响应的配置一律显示成 `sk-BSp******r4si`。
   只有服务端内部调 `get_provider()` 才拿得到明文，用于真正发起请求。
3. **管理密码**：PBKDF2-HMAC-SHA256（12 万次迭代 + 16 字节随机盐）存哈希，
   落在 `data/admin.json`。**没有默认口令**，首次打开 `/admin` 由使用者自己设定。
4. **会话令牌**：HMAC 签名 + 12 小时过期，放在 `HttpOnly; SameSite=Lax` Cookie 里，
   前端 JS 读不到，页面即使出现 XSS 也拿不走凭证。
5. **登录限速**：同一 IP 连续 6 次密码错误锁定 5 分钟。
6. **忘记密码**：停止服务 → 删除 `data/admin.json` → 重启后重新设置。服务端不留后门。

## 生成结果存在哪

**服务端不保存任何生成图片。** 图片以 data URL 直接回给浏览器，
前端转成 `ArrayBuffer` 存进本机 **IndexedDB**（`wb-image-studio`）：

- 库内**拆两张表**：`meta` 放元数据 + 360px 缩略图，`blobs` 放原图字节。
  如果混在一张表里，画廊遍历游标会把每张 2MB 的原图都读进内存——
  50 张就是 100MB 的 I/O。拆开后画廊只读几十 KB 的缩略图，点开灯箱才取原图。
- 记录提示词、模型、尺寸、工具、时间、收藏等元数据，支持搜索与筛选。
- 清空浏览器数据即彻底消失；`data/` 目录里除了配置没有任何图片。
- 支持 `/image#projects` 深链直达作品库。

## 中转站协议（实测结论）

对接过程中验证出四条关键事实，都写进了 `app/image_gen/client.py`：

1. **参照图走 `/v1/images/generations` 的 `image` 字段**（data URL），
   而不是标准 `/v1/images/edits`——后者在这类中转站上直接返回空 `data`。
2. **多参照图同样走 `image` 字段，传数组即可**，不必退化成拼图。
   实测（洋红底白方块 + 青底黑三角两张强特征图）：结果图洋红占比 75.3%、
   青 19.3%，**两张都被采纳**。前端仍保留"被拦时自动改拼图重试"的兜底。
3. **`b64_json` 返回的是 data URL**（带 `data:image/png;base64,` 前缀），
   不是纯 base64；直接解码会因长度非 4 的倍数而报错，需要先剥前缀再补 padding。
4. 内容被拦截时接口可能返回 **HTTP 200 + 空 data**，需要显式识别并给出提示。

## API

| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `/api/health` | OCR 后端状态、字体数量 |
| GET | `/api/fonts` | 字体族列表（`user: true` 表示来自自定义目录） |
| POST | `/api/fonts/upload` | 导入字体文件（multipart，字段名 `files`，可多选） |
| GET | `/api/fonts/user` | 自定义字体目录路径与其中的文件 |
| DELETE | `/api/fonts/user/{name}` | 删除自定义字体文件 |
| POST | `/api/fonts/reload` | 重新扫描字体目录 |
| POST | `/api/analyze` | 上传图片 → 文字块 + 坐标 + 样式；返回 `session_id` |
| POST | `/api/preview` | `{session_id, id, edit}` → 局部补丁 PNG（前端实时预览用） |
| POST | `/api/apply` | `{session_id, edits}` → 结果图 base64 + 统计 |
| POST | `/api/export` | 同上，直接返回文件流（一键下载） |
| GET | `/api/session/{id}` | 读回内存里的会话（不重跑 OCR），用于切页后恢复 |
| POST | `/api/preview-batch` | 一次取多处改动的预览补丁 |

`edit` 对象字段（全部可选）：

```jsonc
{
  "text": "替换后的文字",      // 留空字符串 = 仅擦除
  "family": "Microsoft YaHei",
  "font_size": 32,             // 绝对字号；留空则按原墨迹高度反推
  "font_scale": 1.15,          // 相对缩放（与 font_size 二选一）
  "fg_color": [24, 90, 190],   // RGB
  "bold": false,
  "italic": false,
  "align": "left",             // left | center | right（水平）
  "valign": "bottom",          // bottom | center | top（垂直基准，默认底对齐）
  "offset_x": 0, "offset_y": 0,
  "letter_spacing": 0,
  "erase_method": "auto",      // auto | fill | linear | inpaint | ns | blur
  "auto_fit": false,           // 默认关；开启后过宽时缩字号压回原宽度
  "match_sharpness": true,
  "auto_family": true,         // 按字形自动匹配字体；指定 family 时自动失效
  "match_stroke": true         // 闭环校准笔画粗细
}
```

## 已知限制

- **字体识别是"匹配"而非"识别"**：系统从常用字体里挑最像的（命中率约 8/9），
  而不是报出字体的真实名称——精确识别需要字形分类模型。
  若自动匹配不理想，可在下拉框手动指定；艺术字/手写体（如 Comic Sans）会退化为最接近的常规字体。
- 极端背景（强噪声照片、文字压在复杂图案上）擦除后可能留下轻微痕迹，
  可切换擦除方式、调整字号或微调位置改善。
- 竖排文字、艺术字/手写体目前按常规横排处理。
- 服务为内存会话模式，重启后需重新上传（会话默认保留 4 小时）。
