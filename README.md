# 图片文字处理工具

扫描图片中的文字，识别其**内容与位置**，还原**字体、字号、颜色、粗细**，
并在原位置做**无痕修改替换**——改完看不出动过手脚。

---

## 快速开始

```bash
# Windows：双击 start.bat，或在终端执行
start.bat

# 通用
python -m app.main                 # 默认 http://127.0.0.1:8000
python -m app.main --port 9000     # 指定端口
```

首次运行如提示缺依赖：

```bash
pip install -r requirements.txt
```

打开 <http://127.0.0.1:8000> → 拖入图片 → 点击文字框 → 改内容 → 导出。

### 操作方式

| 操作 | 说明 |
|---|---|
| 拖入图片 / 选择图片 | 自动 OCR 定位并分析样式 |
| 点击文字框 | 选中，右侧出现属性面板 |

## 自定义字体

系统字体之外，可以把**自己的字体**加进来用于替换。

**方式一（推荐）**：编辑面板 → 字体 → **导入字体**，选 `.ttf` / `.otf` / `.ttc`，
立即生效，不用重启服务。已导入的字体在下拉框里带 `★` 前缀。

**方式二**：把字体文件直接拷进项目根目录的 `fonts/`，点 **重新扫描**（或重启服务）。

说明：

- `fonts/` 的优先级**高于系统字体**，同名族会优先用这里的版本
- `.ttc` / `.otc` 是字体集合，内含多个字体会自动逐个登记
- 删除文件后同样需要「重新扫描」才会从列表消失
- 只接受字体扩展名，且落盘前会校验能否被解析，无效文件不会残留
- 字体文件的增删会让扫描目录的 mtime 变化，缓存自动失效，不需要手动清缓存
- `fonts/` 里的字体文件已在 `.gitignore` 中排除，避免把有版权的商业字体分发出去

## 两大核心能力

### 1. 文字识别与定位

- 输出每个文本块的**四点坐标**（可表达倾斜）与**轴对齐矩形**
- 同一行的碎框自动合并成「文本行」，编辑体验与视觉还原都更自然
- 长边超过 2400px 自动降采样加速，坐标映射回原尺寸

### 2. 无痕修改与替换

这不是"盖一块色块再写字"，整条链路有六处针对"不露痕迹"的设计：

**① 样式反推：颜色**
不用平均值（抗锯齿像素会把颜色拉灰）。做法是以背景色为基准，
取偏离最大的那批像素（真实墨迹核心）的众数颜色。

**② 样式反推：字号**
由**墨迹高度**反推，而不是 OCR 框高度（框含 padding，不可靠）。
且不用经验系数——渲染前会**实测**所选字体参考字的字面比例
（例如微软雅黑汉字 0.908、黑体 0.883、Arial 大写 0.717），
因此换字体后字号依然对得上。

**③ 样式反推：粗细 / 背景**
粗细用「笔画宽度 ÷ 墨迹高度」判定（距离变换峰值），不依赖字体元数据。
背景分为**纯色 / 渐变 / 纹理**三类，各自走不同的擦除策略。

**④ 精确掩膜**
用**局部背景图**（形态学开/闭运算估计）做差分，而不是全局阈值——
后者会把渐变背景整片误判成文字。掩膜只保留与目标框重叠的连通域，
避免擦到上下相邻的行。擦除用途关闭连通域去噪，
否则文字顶部的细小抗锯齿碎片会被当噪点剔除，留下淡淡轮廓。

**⑤ 分级擦除 + 残留自检**

| 背景 | 策略 | 原理 |
|---|---|---|
| 纯色 | `fill` | 用紧贴掩膜外圈的真实像素估色后整块填充（不需要羽化，羽化反而造软边） |
| 渐变 | `linear` | 逐列/逐行用掩膜外侧像素做线性外推，取接缝更平滑的方向 |
| 纹理 | `inpaint` | OpenCV Telea / NS 内容修复 |

擦完会**自动检测残留**（框内边缘能量 ÷ 周边背景边缘能量），
偏高就逐轮加大掩膜重擦，最多三轮。

**⑥ 贴合渲染**
- 4 倍超采样绘制后缩回，边缘平滑度接近系统抗锯齿
- 逐字符布局 + 以基线为锚点，跨字体基线一致、支持字距
- 对齐的是**墨迹外接框**而非 OCR 框，消除字体上升/下降部造成的错位
- **清晰度匹配**：原图若经 JPEG 压缩、文字边缘偏糊，按原图锐度对新文字做等量柔化，否则新字会"太锐"而露馅
- **不因原框宽度而改字号**（默认行为）：字变小比"略超出原位置"更容易被一眼看出来，
  而实际场景里文字旁边多半是空白。只有溢出到会盖住相邻内容（超过 1.8 倍）
  才收敛字号，且不低于原字号的 72%。想主动压回原宽度可在面板勾选「过宽时缩字号」。
- 宽度比较一律用**墨迹 bbox**，而不是渲染图层的画布尺寸——图层左右带有约
  0.35×字号的透明 padding，拿画布宽去比会凭空多出几十像素，
  导致"过宽"判断几乎每次都误命中、字号被无故缩小。
- **垂直按底部（基线）对齐**（默认）：阅读时的视觉锚点是基线，按基线对齐最不容易
  看出被改过。若改成居中，新旧文字墨迹高度稍有不同就会把整行推走。
  可在面板切换为居中 / 顶部。
- 墨迹外接框用 **alpha 阈值**测量，而不是 `getbbox()`——LANCZOS 缩放的振铃会在
  字形外围留下极低 alpha 的伪影，`getbbox()` 会把它算进"内容"，
  实测能让墨迹高度虚高 40px 以上，进而把垂直定位整体带偏。

**⑦ 字体与粗细还原（决定"像不像"的关键）**

字体族用**两阶段匹配**：

1. 用「墨迹宽高比 + 墨迹填充率 + 笔画比」从**常用字体白名单**里筛候选
   （不做白名单限制会选中 ITC Bookman 这类"比例接近但字形无关"的冷门字体）
2. 拿**原文字在图中真实的墨迹轮廓**，与候选字体的渲染轮廓做形状 IoU，取最高者

第 2 阶段是必要的：低维特征区分不了 Segoe UI vs Trebuchet MS、
Helvetica vs Calibri（得分几乎打平），而形状 IoU 是拿真实笔画轮廓直接比，能分辨。
注意匹配用的是**原文字**——那才是图里真实存在、可以和模板比对的形状。

笔画粗细做**闭环校准**：渲染 → 用与测量原图相同的口径测笔画宽度 → 补描边 → 再测，
最多两轮。即使字体本身偏细，也能补到与原图一致；若原文字更细，
会尝试切到同族的 Light / Thin 变体。

匹配前会过滤掉**渲染不出该文本的字体**（例如用 Calibri 去画中文）——
否则墨迹度量整体失真（实测会把字号算成 1.7 倍）。


## API

| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `/api/health` | OCR 后端状态、字体数量 |
| GET | `/api/fonts` | 字体族列表（`user: true` 表示来自自定义目录） |
| POST | `/api/fonts/upload` | 导入字体文件（multipart，字段名 `files`，可多选） |
| GET | `/api/fonts/user` | 自定义字体目录路径与其中的文件 |
| DELETE | `/api/fonts/user/{name}` | 删除自定义字体文件 |
| POST | `/api/fonts/reload` | 重新扫描字体目录 |
| POST | `/api/analyze` | 上传图片 → 文字块 + 坐标 + 样式；返回 `session_id` |
| POST | `/api/preview` | `{session_id, id, edit}` → 局部补丁 PNG（前端实时预览用） |
| POST | `/api/apply` | `{session_id, edits}` → 结果图 base64 + 统计 |
| POST | `/api/export` | 同上，直接返回文件流（一键下载） |

`edit` 对象字段（全部可选）：

```jsonc
{
  "text": "替换后的文字",      // 留空字符串 = 仅擦除
  "family": "Microsoft YaHei",
  "font_size": 32,             // 绝对字号；留空则按原墨迹高度反推
  "font_scale": 1.15,          // 相对缩放（与 font_size 二选一）
  "fg_color": [24, 90, 190],   // RGB
  "bold": false,
  "italic": false,
  "align": "left",             // left | center | right（水平）
  "valign": "bottom",          // bottom | center | top（垂直基准，默认底对齐）
  "offset_x": 0, "offset_y": 0,
  "letter_spacing": 0,
  "erase_method": "auto",      // auto | fill | linear | inpaint | ns | blur
  "auto_fit": false,           // 默认关；开启后过宽时缩字号压回原宽度
  "match_sharpness": true,
  "auto_family": true,         // 按字形自动匹配字体；指定 family 时自动失效
  "match_stroke": true         // 闭环校准笔画粗细
}
```

## 版本管理

项目已初始化 Git 仓库，首个版本标记为 `v1.0.0`。

```bash
git log --oneline --decorate    # 提交历史与标签
git diff v1.0.0 --stat          # 相比 v1.0.0 改了哪些文件
git diff v1.0.0 -- app/         # 只看某个目录的差异
git checkout v1.0.0             # 回到该版本代码（用 git switch - 返回）
```

`.gitignore` 已排除生成物（`samples/out/`）、缓存（`app/.font_cache.json`）、
`__pycache__`，以及 `fonts/` 下的字体文件——最后一项是刻意的：
避免把有版权的商业字体分发出去，所以 **git 仓库里不含你的自定义字体**。

### 打完整快照

需要连同自定义字体一起留档时用快照脚本：

```bash
python tools/snapshot.py                    # 版本号自动取当前 git tag
python tools/snapshot.py --version v1.1     # 指定版本号
python tools/snapshot.py --out D:\backup    # 指定输出目录（默认项目上一级）
```

生成形如 `WB-PS-v1.0.0-20260925-1038.zip` 的包，解压即可运行，
内含源码、测试图与 `fonts/` 下的字体。

**两者分工**：git 管版本演进（可 diff、可回滚），快照是完整离线副本。

## 已知限制

- **字体识别是"匹配"而非"识别"**：系统从常用字体里挑最像的（命中率约 8/9），
  而不是报出字体的真实名称——精确识别需要字形分类模型。
  若自动匹配不理想，可在下拉框手动指定；艺术字/手写体（如 Comic Sans）会退化为最接近的常规字体。
- 极端背景（强噪声照片、文字压在复杂图案上）擦除后可能留下轻微痕迹，
  可切换擦除方式、调整字号或微调位置改善。
- 竖排文字、艺术字/手写体目前按常规横排处理。
- 服务为内存会话模式，重启后需重新上传（会话默认保留 4 小时）。
